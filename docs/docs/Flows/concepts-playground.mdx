Langflow 的 **Playground** 是一个动态界面,可用于实时测试基于 LLM 的 flow。

你可以测试 flow 对不同输入的响应、查看和修改记忆、监控 flow 的输出与逻辑。
例如,你可以确认代理 flow 会针对不同输入调用合适的工具。

**Playground** 让你能快速迭代 flow 的逻辑与行为,更轻松地对应用做原型和打磨。

## 在 Playground 中运行 Flow

要在 **Playground** 中运行 flow,先打开该 flow,然后点击 <Icon name="Play" aria-hidden="true"/> **Playground**。
如果 flow 中有 [**Chat Input** 组件](/chat-input-and-output),输入提示词或[使用语音模式](/concepts-voice-mode)即可触发 flow 并开启聊天会话。

要放大 **Playground** 视图,点击 **Playground** 面板中的 <Icon name="Expand" aria-hidden="true"/> **Enter fullscreen**。

![Playground 激活状态下的 Langflow 可视化编辑器](/img/playground.png)

:::tip
如果 **Playground** 中没有消息输入框,请确认 flow 里有 **Chat Input** 组件,且它直接或间接连接到 **Language Model** 或 **Agent** 组件的 **Input** 端口。

**Playground** 面向以问答形式使用 LLM 的 flow(如聊天机器人和代理)设计,因此 flow 必须包含 **Chat Input**、**Language Model**/**Agent** 和 **Chat Output** 组件,才能被 **Playground** 聊天界面完整支持。

对于需要其他输入类型的 flow,例如 webhook 事件、文件上传或文本输入,你可以[用 Langflow API 触发 flow](/api-flows-run),之后再打开 **Playground** 查看该次运行的 LLM 活动(如适用)。
:::

![Playground 窗口](/img/playground.png)

关于 **Playground** 工作原理的技术细节,参见 [Monitor 端点](/api-monitor)。

### 查看代理逻辑

如果 flow 中有 **Agent** 组件,**Playground** 会打印代理使用的工具和每个工具的输出。
这有助于你监控代理的工具使用,理解代理响应背后的逻辑。

### 响应 Human-in-the-Loop 提示

当 flow 因 [**Human Input** 组件](./human-input)或 [**Agent**](./agents) 暂停等待人工批准时,**Playground** 会提示你批准或拒绝该工具调用。

选择一个动作即可从暂停处恢复运行。

更多信息参见 [Human-in-the-Loop](./human-in-the-loop)。

### 查看聊天历史 {#view-chat-history}

在 **Playground** 中,你可以查看 flow 各聊天会话的消息日志,包括时间戳、内容和发送者。

在 **Playground** 侧边栏中找到想查看的聊天会话,点击 <Icon name="Ellipsis" aria-hidden="true"/> **Options**,然后选择 **Message Logs**。

![Playground 日志](/img/messages-logs.png)

消息日志会把每条聊天消息的 [`Message` 数据](/data-types#message)拆解展示。
点击消息日志中的任意单元格,可查看该单元格的完整内容。

### 在 Playground 中修改记忆

为了方便调试和测试 flow,你可以在[消息日志](#view-chat-history)中编辑或删除单条消息。
例如,你可能想删除测试某个已从 flow 中移除的组件时发出的消息。

你也可以从侧边栏删除整个聊天会话:点击 <Icon name="Ellipsis" aria-hidden="true"/> **Options**,然后选择 **Delete**。

如果你继续该聊天会话,或跨多个会话保留记忆,修改记忆会影响聊天机器人的响应行为。

**编辑消息日志会直接修改 Langflow 内部的 `messages` 表,即默认的聊天记忆存储。**
关于在 Langflow 中管理会话和聊天记忆的更多信息,参见[使用自定义会话 ID](#session-ids)和[内存管理选项](/memory)。

## 设置自定义会话 ID {#session-ids}

聊天会话由会话 ID(`session_id`)标识,它是每次 flow 运行的唯一标识符。

默认会话 ID 是 flow ID,这意味着一个 flow 的所有聊天消息都存在同一个会话 ID 下,形成一个超大的聊天会话。

如果需要跨多次 flow 运行保留聊天上下文,或在调试 flow 时区分不同聊天会话,可以设置自定义 `session_id`。

自定义会话 ID 的用处:

* 当一个 flow 存在多个聊天会话时(例如聊天机器人同时服务多个用户),分离各聊天会话。
* 跨多次 flow 运行继续聊天,或在 flow 之间传递上下文时保留记忆。
* 区分同一 flow 中多个用户的活动。
* 调试和测试 flow 时识别自己的聊天会话。

你可以在可视化编辑器中或以编程方式设置自定义会话 ID。

<Tabs>
<TabItem value="visual" label="可视化编辑器" default>

在你的[输入输出组件](/chat-input-and-output)中使用 **Session ID** 字段:

1. 点击要设置自定义会话 ID 的组件。
2. 在[组件检查面板](/concepts-components#component-menus)中,启用 **Session ID**。
3. 点击 **Close**。
4. 输入自定义会话 ID。
   如果该字段为空,flow 使用默认会话 ID。
5. 打开 **Playground**,即可在你的自定义会话 ID 下开始聊天。

想开始新的聊天会话、或以不同会话 ID 继续早前会话时,记得修改 **Session ID**。

</TabItem>
<TabItem value="api" label="Langflow API">

使用 Langflow API 触发 flow 时,在请求 payload 中带上 `session_id` 参数。
例如:

```bash
curl -X POST "http://$LANGFLOW_SERVER_ADDRESS/api/v1/run/$FLOW_ID" \
-H "Content-Type: application/json" \
-H "x-api-key: $LANGFLOW_API_KEY" \
-d '{
    "session_id": "CUSTOM_SESSION_ID",
    "input_value": "message",
    "input_type": "chat",
    "output_type": "chat"
}'
```

该命令会以指定的 `session_id` 开启新聊天会话;若已有同 ID 会话,则获取该会话。

</TabItem>
</Tabs>

:::tip
生产环境中,建议会话 ID 使用变量而不是硬编码值。

例如,要为已认证用户保留上下文,用户 ID 就是会话 ID 的理想变量。
如果希望每次聊天都唯一,可以为每个会话 ID 自动生成 UUID。
:::

更多信息参见[使用会话 ID 管理组件间通信](/session-id)。

## 分享 Flow 的 Playground

:::warning
**Shareable Playground** 仅用于测试。
**Playground** 不是用来把 flow 嵌入应用的。关于在应用或网站中运行 flow,参见[用 Langflow API 触发 flow](/concepts-publish)。

**Shareable Playground** 在 Langflow Desktop 上不可用。
:::

**Shareable Playground** 选项会把单个 flow 的 **Playground** 暴露在 `/public_flow/$FLOW_ID` 端点。

[部署公网 Langflow 服务器](/deployment-overview)后,你可以把这个公开 URL 分享给其他用户,让他们只能访问指定 flow 的 **Playground**。
对方无需安装 Langflow,也无需生成 Langflow API key,即可与 flow 的聊天输入输出交互并查看结果。

与其他用户分享 flow 的 **Playground**:

1. 在 Langflow 中打开要分享的 flow。
2. 在[工作区](/concepts-overview#workspace)中点击 **Share**,然后启用 **Shareable Playground**。
3. 再次点击 **Shareable Playground**,打开 **Playground** 窗口。
   该窗口的 URL 就是 flow 的 **Shareable Playground** 地址,例如 `https://3f7c-73-64-93-151.ngrok-free.app/playground/d764c4b8-5cec-4c0f-9de0-4b419b11901a`。
4. 把 URL 发给其他用户,他们即可访问该 flow 的 **Playground**。

默认情况下,共享的 **Playground** 无法运行包含自定义组件的 flow,因为该运行未经认证,Langflow 只会执行该路径下它自己副本中的组件。确需运行,可在服务器上通过 `LANGFLOW_COMPONENTS_PATH` 安装该组件。更多信息参见[公开分享 flow 中的自定义组件](/deployment-block-custom-components#public-flow-custom-components)。
