Langflow GitHub 仓库是 [Langflow 社区](/contributing-community)的重要组成部分。

除了通用的 Langflow 使用帮助外,这个仓库还是报告 bug 和请求功能增强的最佳场所,可以确保这些问题被 Langflow 维护者跟踪处理。

## GitHub issues

[Langflow 仓库的 Issues 页面](https://github.com/langflow-ai/langflow/issues)会持续更新 bug 和功能请求。

:::tip
推动某个请求或 bug 得到处理,最好的方式是在已有 issue 下留言。
活跃度高的 issue 更容易获得贡献者的关注。

报告 bug 或提交功能请求前,请先搜索是否已有类似 issue。
可以借助 [Langflow 仓库的标签](https://github.com/langflow-ai/langflow/labels)筛选搜索结果。
:::

## GitHub discussions

如果你的代码或 Langflow 使用本身需要帮助,可以访问 [Langflow GitHub Discussions 页面](https://github.com/langflow-ai/langflow/discussions),或通过其他 [Langflow 社区](/contributing-community)渠道求助。

Langflow 团队不提供一对一的邮件支持,团队认为公开讨论凭借可检索性,能帮助到更多用户。

## 社区准则与技巧

Issues 和 Discussions 页面都是公开的,Langflow 团队请你提交问题和 issue 时遵循以下准则:

* **尽量提供详细的信息**:只说"某个功能不好使"没有意义。Langflow 团队需要细节才能复现和定位问题。
* **说清楚到底哪里出了问题**:附上报错信息和 _如何_失败的过程描述,而不只是"它失败了"这个事实。
* **回顾你的操作步骤**:说明报错前发生了什么、你原本期望的结果,以及你近期做过的改动,例如升级了 Langflow 或某个依赖。
* **描述你的环境**:写明操作系统、Langflow 版本、Python 版本,以及其他可能与问题相关的环境信息。
* **附上失败代码的片段**:务必隐去敏感值,只提供与故障相关的部分,而不是整个脚本。提供代码片段能大幅提升复现错误、排查问题和给出具体建议的效率。
  * 如果提交中包含大段代码、日志或堆栈跟踪,请用 [details 标签](https://developer.mozilla.org/en/docs/Web/HTML/Element/details)(`<details> 把代码贴在这里 </details>`)折叠内容,让提交更易读。
* **省略敏感信息**:除公开 GitHub 资料中的信息外,不要包含安全密钥、全名、身份证件号码、住址、电话号码等敏感或可识别个人身份的数据。
* **保持友善**:任何软件的 bug 都可能让人抓狂,但请记住,读到你消息的是真心想帮忙的真人。不必刻意甜言蜜语,但也没必要靠粗鲁来换取支持。
  * 你的 issue 和讨论都挂在你的 GitHub 账号下,互联网上的任何人都能看到,包括你现在的和潜在的雇主与同事。
  * Langflow 仓库是公开的 GitHub 仓库,因此适用 [GitHub 社区行为准则](https://docs.github.com/en/site-policy/github-terms/github-community-code-of-conduct)。
